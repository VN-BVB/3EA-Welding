# 标定算法待确认事项

本文只记录重构过程中确认存在的算法风险，本次结构整理不修改这些行为。

1. `CalibrationConfig::getCameraIntrinsics` 接受 4 个或 5 个畸变系数，但当前始终按 1×5 构造矩阵。输入只有 4 个元素时存在越界读取风险。
2. `CoordinateCalculation::projectPointToAxis` 不是正交投影，而是用指定坐标分量计算参数 `t = point[component] / direction[component]`。这依赖所选方向分量非零。
3. 坐标查询中 X 轴目标编码器值为“当前编码器值 + 移动量”，Y/Z 轴目标值直接使用投影参数；三轴语义是否应一致需要结合机械结构确认。
4. 外轴标定中 X 轴矩阵直接使用手眼矩阵并把平移从米换算为毫米；Y/Z 轴还会减去“方向向量 × 参考编码器值”。该差异目前按既有机械假设保留。
5. 圆点板检测先执行一次 `bitwise_not`，随后逐像素再次反色，两次操作相互抵消。
6. 文件夹圆点检测失败时只保留成功图片的点集，并把失败图片重命名；手眼流程随后只比较成功点集数量与位姿数量，可能失去原图片与位姿的一一对应关系。
7. 样本标准差使用 `n - 1` 作分母；只有一个有效样本时会除以零。
8. `cv::calibrateHandEye` 的输出按 OpenCV 定义是相机到夹具的变换，但现有数据字段和流程使用 `cameraToBaseMatrix` 命名。需要结合实际眼在手外安装关系重新确认语义，本次不改矩阵计算。
