## 2. ◮◮◮ 多人协作代码准则:
1. 作为项目仓库的建立者, 我们承诺让每个人都能在参与我们的项目时免受骚扰. 无论年龄、体型、可见或不可见的残疾、种族、性别特征、性别认同和表达、经验水平、教育程度、社会经济地位、国籍、外貌、种族、宗教信仰或性认同和性取向如何, 我们承诺都将一视同仁. 构建包容的环境对于促进人工智能和计算机视觉等领域的创新至关重要.

2. 在您书写代码时, 请确保函数、变量、类名、注释等都能清晰地表达您的意图, 并避免使用不明确或可能引起误解的词语. 我们期待您的代码能够被其他开发者理解, 并能在不产生混淆的情况下被正确使用.

3. **命名准则:** 我们强烈建议您的代码命名符合以下命名准则:
   1. 函数名使用小驼峰命名法, 例如`void initStructLightCamera()`, 尽可能使用动词开头;
   2. 变量名也使用小驼峰命名法, 例如`structLightCamera`;
   3. 类名使用大驼峰命名法, 例如`RailWeldingSystem`;
   4. 枚举、预编译宏以及常量使用下划线全大写命名法, 例如`enum WELD_TYPE { BACK_CORNER_BUTT, FRONT_CORNER_BUTT, BACK_BEAM_BUTT, FRONT_BEAM_BUTT, FRONT_HORIZONTAL_FILLET, FRONT_VERTICAL_FILLET }`;
   5. 对于Qt中的组件, 我们建议您保留Qt原本的命名, 去除首字母Q以及后缀序号，并在后面跟上组件的功能或作用, 同时仍然遵循小驼峰命名法. 例如, `QPushButton`的命名可以是`btnStart`或`pushButtonStart`, `QComboBox`的命名可以是`comboBoxWeldType`等;
   6. 注释使用中文, 并在必要时使用英文辅助理解.

4. **信号和槽的使用:** 我们建议您的信号尽可能使用`send`作为开头, 槽尽可能使用`when`作为开头. 除非信号和槽中的参数只是简单的类型, 例如`int, double, bool`等, 否则请使用智能指针传递. 由于`cv::Mat`和`pcl::PointCloud`内部实现了引用计数, 因此不需要使用智能指针传递.

5. **模块搭建:** 每一个功能模块都应当尽可能独立, 并在`./src`文件夹中独占一个子文件夹, 使用一个pri文件管理该模块. 在代码层面上, 除UI模块以外, 其余各功能模块原则上都需要独占一个子线程, 并务必不要使用继承`QThread`的方式实现, 而是使用继承`QObject`并`moveToThread`的方式实现. 在构建模块以及创建新类时, 应当充分考虑C++面向对象的特性, 不应在代码层面打破面向对象的设计原则. 例如, 结构光传感器中(如)有主副两个相机, 那么在代码层面就应当有两个对象, 而不是一个对象中包含两个相机. 这样做的好处是, 可以让代码更加清晰, 易于维护, 并减少错误的发生, 并提高代码的复用性和灵活性.

6. **单一职责:** 我们建议您的函数、类、变量等尽可能只负责一件事情, 例如相机类只负责采集图像, 不负责处理图像, 图像的处理在对应的功能模块中进行. 同理, UI类以及各个UI模块类只负责『显示信息』和『响应交互』, 不负责处理信息和处理项目模块之间的逻辑交互关系, 处理信息请在各个子模块中进行, 各模块之间的逻辑交互请在`RailWeldingSystem`类中进行. 这样可以使代码更加清晰, 易于维护, 并减少错误的发生.

7. **子线程创建:** 对于已经是独立模块的子线程模块来说, 我们建议您在其中继续创建子线程时遵循以下原则:
   1. 该模块中需要进行计算密集型的操作, 例如点云的处理等, 必要时请使用`src/utils/common/ThreadPool`的线程池类进行管理;
   2. 该模块中的各个子模块需要同时工作, 例如结构光相机模块中的投影仪模块和相机模块;
   3. 如果该模块中的各个子模块工作是串行的, 例如分割方法定位焊缝模块中的图像分割子模块, 其它操作必须等待图像分割完成后才能继续进行, 此时不建议为图像分割单独创建一个子线程, 而是在图像分割子模块中进行操作, 以确保代码更加清晰简洁, 易于维护.

8. **UI类型选择:** 我们强烈建议各个模块的主UI类型选择为`QWidget`, 而不是`QMainWindow`. 这是因为`QMainWindow`包含了许多额外的功能, 例如菜单、工具栏、状态栏等, 而这些功能在我们的项目中并不是必要的. 此外, 由于项目主UI使用的是`QMainWindow`, 如果模块的UI也选用`QMainWindow`, 将不利于项目的便捷整合. 因此, 我们建议您只使用`QWidget`来创建您的UI.

9. **降低模块间的编译依存:** 我们建议您的模块之间的编译依存关系越少越好. 例如, 结构光相机模块需要依赖相机模块和投影仪模块, 那么在结构光相机类的头文件中, 不要直接包含相机模块和投影仪模块的头文件, 而应使用前向声明的方式, 例如`class Camera; \ class Projector;`, 并在成员属性中采用指针或智能指针的方式声明相机模块和投影仪模块的对象. 这样可以减少模块之间的编译依存关系, 并提高编译速度. 并在源文件中包含对应模块的头文件.

10. **代码排版:** 我们建议您的代码排版符合Google C++ Style Guide, 并在Qt Creator中安装clang-format格式化插件, 以确保代码的排版整齐. 在符合谷歌风格的代码排版基础上, 做以下进一步要求:
    1. 每一级缩进使用4个空格;
    2. `public: / protected: / private:`在类中的缩进为0, 即无缩进;
    3. 对其数组或类似数据结构中的元素, 采用左对齐方式排版, 以便于阅读, 例如:
        ```
        struct test demo[] =
            {
                {17,  'A', "hello"},
                {6,   'B', "world"},
                {606, 'C', "!"    }
            };
        ```
    4. 每行最多编写150个字符, 超过150个字符时, 请在适当的位置换行, 并保持代码的可读性;
    5. 其它规范, 例如操作符前后添加空格; 大括号位置等, 保持与Google C++ Style Guide一致;
    6. 上述规范对应的`clang-format`参数为: 
        ```
        {
            BasedOnStyle: Google,
            IndentWidth: 4,
            AccessModifierOffset: -4,
            AlignArrayOfStructures: Left,
            ColumnLimit: 150,
        }
        ```

12. **其它细节:** 其它需要遵守的代码编写细节, 列举如下:
